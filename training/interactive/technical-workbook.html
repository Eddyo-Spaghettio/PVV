Module 1: Discovery Before Building

The most common technical mistake is building something the client didn't need, can't maintain, or already had. Ask first.

Five questions before any build

  1. What problem are we solving?
  2. Who will use this?
  3. Who maintains it after we leave?
  4. What's the timeline?
  5. What's the budget? ($0 is the default)
Red flags "We need an app" (usually means a form). "Make it like [big nonprofit]" ($500K budget). "We need it Friday" (it's Wednesday). No one on their team can update content.

Tool decision guide

NeedUse this (free)
Simple website / Reach PageGoogle Sites
More design controlWix (free tier)
Forms / sign-upsGoogle Forms or Tally.so
DonationsGivebutter, PayPal Donate, Stripe link
Data trackingGoogle Sheets (linked to Forms)

Default recommendation: Google Sites + Google Forms + Google Sheets. The client probably already has Gmail. No coding. You can hand off in 15 minutes.

Module 2: Building the Reach Page

The Reach Page is the centerpiece of Bridge Kit. One mobile-friendly page where someone can volunteer, donate, or learn more - in under 2 minutes.

Standard 5-page site (when client needs more than a landing page)

PageMust have
HomeMission, hero image, 3 quick links, donate button
AboutStory, team, 501(c)(3) info, impact numbers
ProgramsWhat you do, who qualifies, how to access
Get InvolvedVolunteer form, donate button
ContactForm, email, phone, address, map

Build sequence

Week 1: Intake + collect logo, photos, copy
Week 2: Draft copy in Google Doc (client edits here, not in builder)
Week 3–4: Build pages. Embed forms. Add alt text to every image.
Week 5: Test on mobile. Click every link. Submit every form.
Week 6: Client approval → publish → handoff doc

The 5-second test A new visitor should understand: what this org does, who it helps, and what they can do - within 5 seconds of landing on the page.

Module 3: Forms, Data, and Handoff

You're often handling sensitive information for vulnerable people. Build carefully. Hand off cleanly.

The standard pipeline

Google Form → Google Sheet → (optional) simple dashboard → monthly report

Form design rules

  • Only ask what you need - minimum data collection
  • Use dropdowns instead of free text when possible (cleaner data)
  • Include a consent checkbox ("I agree to be contacted")
  • Enable email notifications for new submissions
  • Set Sheet permissions to specific emails - never "anyone with link"

Privacy rules (non-negotiable)

Never store client data in your personal Google account long-term. Never share PII in PVV meetings. The client owns the data - hand off all accounts.

Handoff doc (required for every project)

Write a one-page guide for the client covering:

  • How to check new form submissions
  • How to edit website text
  • How to update the donate link
  • Who to contact if something breaks (you, during transition period)
